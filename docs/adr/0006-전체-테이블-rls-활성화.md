# ADR 0006: 모든 테이블에 RLS(행 단위 보안) 활성화

## 상태
확정 (2026-09-28)

## 문제
Supabase는 `public` 스키마 테이블을 PostgREST 자동 REST API로 `anon`/`authenticated`
역할에게 공개한다. RLS가 꺼져 있으면 프로젝트 URL과 anon 키만으로 `admins`(비밀번호 해시),
`reports`(신고 내용) 등을 외부에서 읽고 쓸 수 있다. 우리는 이 자동 API를 쓰지 않고
backend/ai가 DB에 직접 접속하는 구조다.

## 검토한 대안
1. RLS 켜고 정책 없음 → 자동 API로는 아무것도 못 읽고 못 씀
2. 테이블별로 필요한 읽기 정책만 추가
3. 자동 API 스키마 노출 설정 자체를 끄기 (대시보드 설정)

## 결정
1번. 마이그레이션 `0003_enable_rls`로 전체 테이블(+`alembic_version`)에 RLS를 켜고 정책은
만들지 않는다. 새 테이블을 추가하는 마이그레이션에도 `ENABLE ROW LEVEL SECURITY`를 반드시
포함한다 (명세서 5장 규칙).

## 트레이드오프
- 나중에 Supabase 자동 API·Realtime을 쓰고 싶어지면 정책을 따로 설계해야 함
- 새 테이블에서 RLS를 빼먹으면 그 테이블만 노출됨 → 명세서·마이그레이션 템플릿 주석으로 방지

## 왜 이렇게 결정했는지
backend/ai는 테이블 소유자(`postgres`)로 접속해서 RLS의 영향을 받지 않으므로 기능 변화가
전혀 없고, 비용은 마이그레이션 파일 하나다. 3번은 대시보드 수동 설정이라 코드로 이력이 남지
않고, 2번은 쓰지 않는 기능을 위한 설계 비용이다.
