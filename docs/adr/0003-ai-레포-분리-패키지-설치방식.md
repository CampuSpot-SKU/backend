# ADR 0003: AI 레포 분리 + 패키지 설치 방식 (최초 결정 — 0004에서 뒤집힘)

## 상태
**Superseded by [0004](0004-ai-서비스-완전분리-cloud-run.md)** — 이 문서는 이력 보존용으로만 남김.

## 문제
프론트/백엔드/AI 코드를 어떤 단위로 레포를 나눌지, 그리고 나눈다면 배포 단위도 같이 나눌지 결정 필요.

## 최초 결정 (이후 뒤집힘)
레포는 `backend`/`frontend`/`ai` 3개로 나누되, 배포되는 서비스는 backend/frontend
2개만 유지하고 `ai`는 backend가 pip 패키지로 설치해서 같은 프로세스 안에서 함수처럼
호출하는 방식으로 결정.

## 이유(당시)
마이크로서비스로 쪼개면 네트워크 호출·레이턴시·에러 핸들링이 새로 생기는데, 5.5주
기간엔 그 비용이 얻는 것보다 크다고 판단.

## 왜 뒤집혔는지
AI 관련 로직 비중이 실제 개발을 진행하면서 예상보다 커져서, backend 코드와 완전히
분리해서 독립적으로 관리·배포하고 싶다는 요구가 생김. 자세한 내용은 0004 참고.
